---
title: Internationalization (i18n)
description: The locales the system speaks — labels become keys at generation
---

The project declares its **locale catalog**: the languages the system speaks and
the default one.

```json
{ "kind": "set-project-locales", "fieldIds": ["es-ES", "en", "de"], "label": "es-ES" }
```

(`fieldIds` carries the locales, `label` the default — also editable through the
project's form and MCP.)

**Every literal of the model is a translation key in waiting**: menu labels, page
names and zones, button labels, field labels from PageFieldConfig, wizard step
labels, notification subjects and bodies. With more than one locale declared,
generation emits them as keys with the default locale's bundle pre-filled, and one
bundle per additional locale to complete — instead of hard-coded strings.

Single-locale projects (the default) generate plain literals: declaring i18n is
opting in, not a tax.
