## What is Modux?

Modux is a **model-driven code generation framework** for building **enterprise information systems** in Java with Domain-Driven Design. It targets the long-lived, business-critical systems made of several bounded contexts that must hold invariants, run business processes, and integrate with each other — not just forms over tables. You describe your domain using YAML files and Modux generates a fully structured Spring Boot application following hexagonal architecture — with domain, application, infrastructure, and UI layers — so your team can focus on business logic instead of boilerplate.

See [Enterprise Information Systems](/getting-started/enterprise-systems/) for *why* Modux ships the patterns it does, each derived from what such a system actually requires.

## Built for the AI era

When an AI agent builds software, **every line it writes — and later re-reads — costs tokens**.
With Modux the agent authors the *model* and the business hooks; the rest of the system is
emitted by deterministic, tested templates at zero token cost, with no review-and-fix loops
over boilerplate.

Not an estimate — [measured on a real case study](/reference/case-study-booking/), where the
same agent implemented the same spec both ways: writing the system directly cost **~31 output
tokens per delivered line**; the Modux path cost **~16 even while building 15 generator
features it was missing** — for a six-microservice system instead of a monolith — and the next
app pays only the model and hooks: **~4 tokens per line, roughly 8× cheaper**. The gap keeps
widening with every evolution: a few YAML lines regenerate thousands across services for free,
and future sessions reason over a 2,777-line model instead of re-reading a 26,000-line
codebase.
